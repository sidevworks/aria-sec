# ARIA — Full Function Reference

> Complete function-level reference for the ARIA backend (`server/`), generated by
> reading the live codebase. Covers ~885 functions across ~60 modules, organized by
> subsystem. The backend is where all real logic lives; the React/Three.js front end
> is summarized at component level in Part 11.
>
> **Status legend:**
> `✅ working` · `⚠️ works, caveated` · `🔌 needs credentials/config` · `💤 built, not wired` · `❌ stub/broken`
>
> **Model note:** conversational/narration/voice and the Decision Engine run on **Gemini 2.5
> Flash** via `GOOGLE_API_KEY` (falls back to `GEMINI_API_KEY`). The Claude path
> (`callClaude`) is intentionally dormant (no `ANTHROPIC_API_KEY` set) to control cost.

## Known caveats (cross-cutting)

1. **Remediation generator** is templated, not LLM-written (`aiSpmRemediationGenerator`).
2. **`callClaude` dormant** by design (Gemini is the live engine).
3. **Importing the server auto-starts the reasoning + auto-scan schedulers** — keeps test processes alive unless stopped.
4. **`policyStore` has legacy + new API duplication** (tech debt).
5. **Encryption-at-rest is opt-in** — needs `ARIA_CREDENTIAL_ENCRYPTION_KEY` (64-hex).
6. **Demo modes** (AI-SPM, identity, network) are explicit per-request toggles, **off by default** — never fake-by-default.
